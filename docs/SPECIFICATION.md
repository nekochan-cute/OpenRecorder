# 機能仕様・受け入れ条件

## 目的と根拠

対象はColorOS 16/17のレコーダーの主要な機能です。画面の忠実な複製は要件に含めず、操作の結果を独立した実装で提供します。記載する動作は、本プロジェクトの仕様です。ColorOSの全機能を実機で観察した結果ではありません。

ColorOS 16の公式紹介では、リアルタイム文字起こし、話者識別、自動タイトル、要約、用途別テンプレート、音声/全文/要約の共有を確認しました。17のレコーダーの個別差分は未確認です。

## 録音・保存

- マイク権限を得た、画面が表示されている状態からマイク用フォアグラウンドサービスを起動します。
- 入力は16bit PCM、16kHzまたは48kHz、モノラルまたはステレオです。非対応形式ではエラーを表示します。
- 一時停止中は入力を停止し、停止時間を音声に含めません。経過時間は保存したフレーム数から算出します。
- WAVを直接逐次書き込みし、ヘッダーを約1秒ごとに更新・fsyncします。正常停止時は最終長へ更新します。
- 音声認識の遅延や失敗によってPCM保存を待機させません。キュー過負荷時は認識を中断します。
- 通知と画面から一時停止/再開/保存停止を操作できます。
- 入力の希望デバイスと実際のデバイスは区別し、録音画面に実際の入力名を表示します。
- 中断を示す管理情報がある場合、次回起動時にファイルの実サイズからヘッダーと録音時間を修復します。未完成の最終フレームは切り落とします。

受け入れ条件: 10秒録音→5秒一時停止→10秒録音したファイルは、約20秒です。画面消灯・アプリ切り替えで録音を継続します。強制停止から回収した音声は、実際に残ったフレーム数と時間が一致します。メーカーの省電力制御とプロセス終了は実機で確認します。

## 管理・保全

- 管理情報は`AtomicFile`で一括保存し、保存に成功した状態をStateFlowへ公開します。
- 音声・画像・管理情報はアプリ専用ストレージです。読み取りURIは共有操作でのみFileProviderから付与します。
- ごみ箱は自動消去しません。復元か明示的な完全削除で処理します。
- 完全削除は一時的な削除名へリネームして管理情報を更新します。中断時は管理情報に従って復元・削除を完了します。
- 他の録音から参照される写真は、編集元の完全削除で消去しません。
- 管理情報が破損した場合は元のJSONを退避し、読めるWAVを回収します。読めない音声は削除しません。

## 編集・タイムライン

- 編集は元音声を残して、新しいIDとWAVで保存します。
- 選択区間を残すか、選択区間を削除して前後を接続します。
- コピー単位はチャンネルフレームです。ステレオの左右対応を崩しません。
- 残った区間のマークを移し、削除された位置のマークを除きます。
- 完全に残った文章は時刻を移します。切断された文章を全文そのまま残すと不正確なため除去します。要約は編集版へ引き継ぎません。
- 文字起こし/話者名を修正した場合は、古い要約を消去します。

受け入れ条件: 3秒の音声から1〜2秒を削除すると2秒になり、2.5秒のマークは1.5秒へ移ります。元音声のバイト列は変化しません。全区間の削除は拒否します。

## 文字起こし・話者・要約

- 共通の文章形式は`startMs, endMs, text, speaker`です。`speaker`は任意です。
- Voskによる端末内認識と、HTTPS APIの録音後認識に対応します。
- APIが話者ラベルを返す場合に取り込みます。端末内の自動話者分離は未実装です。
- 文章/話者の手修正、話者名の一括変更、文章位置へのシークを提供します。
- 要約はChat Completions形式のAPIを使用します。原文を資料として扱い、原文にない事実を足さないよう指示します。結果の正しさを保証する仕様ではありません。
- 用途別テンプレートは会議・講義・インタビューです。結果からタイトルと本文を分けて保存します。
- AI機能の再実行では既存結果の上書きを確認します。音声の原本は上書きしません。
- モデルとキーはソースに埋め込みません。モデルは利用者がライセンスを確認して導入します。

## 非対象・残作業

指向性録音、OPPO独自DSP、同一音質の保証、端末内話者分離、端末内LLM、翻訳、AAC/M4A/MP3対応、結合、後処理のノイズ除去/音量正規化は今回の開発版に含みません。公開前の端末テストとColorOS 16/17での観察は別途必要です。
